### Checked and correct

Worth recording because they are the things most likely to be wrong:

- **Upload allow-list.** `evil.svg` (an SVG carrying `<script>alert(1)</script>`) is refused with "File type ".svg" is not allowed"; a file with no extension is refused; a 0-byte file gives "That file is empty". All three arrive as one clear toast. A filename with spaces, Khmer and diacritics uploads fine and is stored under a UUID, so the name never reaches the filesystem or a URL.
- **Uploads serve.** PNG, MP4 and PDF all return 200 with the right `Content-Type` and byte count at `/uploads/<uuid>.<ext>`, and an inserted image renders on the public page.
- **Staff permissions.** Every one of 27 admin routes refuses the staff user, and no admin surface 500s. Server-side too: `adminPages.list`, `adminUsers.list`, `adminMedia.list`, `adminRoles.list` and a `adminPages.delete` mutation all return **403 FORBIDDEN**, and `POST /api/media/upload` returns 403. The gate is not just a client redirect.
- **Logged-out access.** All 39 static admin routes redirect to `/login`; none leak, none 500.
- **Logout** invalidates the session; a later `/admin/pages` fetch redirects to `/login`.
- **Session cookie** is `HttpOnly; SameSite=Lax; Path=/`, with `Secure` added when `NODE_ENV=production` (`src/server/auth.ts:143`).
- **Rate limiting** exists and is well-judged: 20/IP/10min, refusals do not extend the window, and the per-account path only delays rather than locking a named admin out (`src/server/ratelimit-core.ts:65-73`). Only the client message is wrong (H4).
- **Duplicate slug** is caught with a useful sentence: "A page already exists at "ui1-audit-page". Choose a different URL."
- **HTML in a text field** is escaped, not rendered: `<script>alert(1)</script><b>bold brief</b>` in Brief comes back as text on the public page, no `<script>` and no `<b>`.
- **No-op save** is prevented - Save is disabled until the form is dirty.
- **Edits persist** across a reload.
- **Delete** works end to end: confirm dialog, Cancel and Escape both leave the row alone, Confirm removes it (42 -> 41 rows).
- **Dialogs trap focus** (three Tabs cycle within the dialog) and are `role="dialog"`, `aria-modal="true"`, labelled. Only the focus *return* is missing (M09).
- **Skip link** is the first tab stop, is visible when focused, and one Tab after activating it lands on "+ New page" inside `main` - the sidebar is genuinely bypassed.
- **Module toggle** works both ways: turning Schools off removes it from the sidebar immediately, `/admin/schools` then redirects to `/admin` rather than 500ing, and turning it back on restores everything.
- **Admin changes reach the public site.** Header donate label and Settings -> Short name both appeared in the public homepage HTML after saving.
- **Rich text** behaves under real keyboard input: H2 applies, Ctrl+B bolds the selection, Ctrl+Z undoes exactly one step, Ctrl+Shift+Z redoes it, table insert works, and the saved body survives a reload and renders on the public page.
- **Console and network are clean.** Across the whole session the only console errors are the ones this audit provoked (401/429/403 from deliberate probes, plus one 404 from a tRPC path I invented). No uncaught application error, and no failed request during ordinary navigation.

### Two notes on method

Two things I first wrote down as defects and then withdrew, because the fault was mine:

- Toasts live 4.5s (`src/components/Dialogs.tsx:77-81`). A separate tool call after a click arrives later than that, so early probes saw an empty DOM and I read saves as failing silently. Everything transient in this report was re-tested by clicking and polling inside a single evaluation.
- Selecting text and inserting list items through raw DOM calls does not drive ProseMirror properly. The bold and list operations that looked broken were re-run with real key presses and are fine.

### Environment caveat

Another pane was editing `src/` throughout. Vite HMR fired repeatedly (`hmr update /src/routes/admin.tsx`, `page reload src/lib/i18n.tsx`, `hmr invalidate /src/components/PdfReader.tsx`) and twice discarded an unsaved editor section mid-test. A `UI Strings` item also appeared in the sidebar partway through the session, which was not there at the start. Nothing in the findings above rests on a state that HMR touched - the editor work was redone inside single uninterrupted interactions - but a rerun on a quiet tree would be worth having.
